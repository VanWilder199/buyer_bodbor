# Дизайн-система покупателя (`apps/web`)

> **Правило для агентов: ничего не запускать.** Не поднимать dev-серверы (`npm run dev:*`, `vite`, `vite preview`), не открывать браузеры (в том числе headless Chrome/Firefox ради скриншотов), не стартовать заглушки бэкенда и любые фоновые процессы, не ходить `curl` на локальные порты. Проверка только статическая: `npm run typecheck`, `npm run build`, юнит-тесты (vitest). Всё, что требует живого приложения (визуальная проверка компонентов, витрина `/dev/ui`, критерии вида «запускается на localhost»), делает и отмечает пользователь сам.
> Причина: в песочнице агент не может убить фоновые процессы (порты 5174 и 8080 остаются занятыми, Spring Boot потом не стартует), а браузер в ней не запускается.

> Визуальный язык приложения покупателя. API и поведение описаны в `PLAN_FRONTEND.md`, этот документ — только про то, **как это выглядит**.
> Ориентир — мобильный веб Т-Банка: берём приёмы, а не бренд (свой акцент, свой логотип, никакого жёлтого `#FFDD2D`).
> **Экран отчёта сюда не входит**, его обсуждаем в конце отдельно. `ReportView` пока остаётся как есть, при переезде ему нужно только подтянуть токены.

## 1. Принципы

Короткий список приёмов Т-Банка, которые работают и не усложняют UI:

1. **Серый фон, белые карточки.** Структура держится на карточках с большим радиусом, а не на рамках, тенях и разделителях.
2. **Одно главное действие на экран.** Одна яркая широкая кнопка, закреплённая внизу экрана. Всё остальное — вторичные кнопки или ссылки.
3. **Списки из ячеек.** Иконка в кружке, заголовок и подзаголовок слева, значение справа. Так выглядят машины, отчёты, покупки — везде одинаково.
4. **Цифры крупно.** Цена и статус — самое заметное в карточке.
5. **Bottom sheet вместо модалок.** На мобильном любые подтверждения и выборы выезжают снизу.
6. **Skeleton вместо спиннеров** для загрузки контента; спиннер только внутри кнопки.
7. **Человеческий текст.** На «вы», коротко, без терминов («Оплата не прошла», а не «Transaction declined»).

**Чего не делаем в MVP (сознательно):** тёмная тема (переменные готовим, значения — потом), таб-бар (разделов всего два: поиск и покупки), иллюстрации, кастомные анимации, сторис-карусели, лендинг с маркетингом.

## 2. Стек

| Что | Выбор | Зачем |
|---|---|---|
| Компоненты | **shadcn/ui** (Radix + Tailwind v4), код компонентов лежит у нас | полный контроль над видом без борьбы с библиотекой |
| Bottom sheet | **vaul** (компонент `Drawer` в shadcn) | нативное поведение свайпа на мобильном |
| Toast | **sonner** (компонент `Sonner` в shadcn) | ошибки мутаций, «Скопировано» |
| Ввод OTP | **input-otp** (компонент `InputOTP` в shadcn) | 6 ячеек, `autocomplete="one-time-code"`, вставка из SMS |
| Иконки | **lucide-react** | один набор линейных иконок, stroke 2 |
| Шрифт | **Onest** (`@fontsource-variable/onest`), запасной — Manrope | хорошая кириллица, близок по ощущению к шрифту Т-Банка. Хостим сами, а не с Google Fonts: CSP `default-src 'self'` |
| Классы | `clsx` + `tailwind-merge` (`cn()` из shadcn), `class-variance-authority` для вариантов | стандартная обвязка shadcn |

**Где живут компоненты:** `packages/ui/src/components/ui/*` (shadcn-компоненты) и `packages/ui/src/components/*` (наши составные). `components.json` лежит в `packages/ui`. Их же использует админка (решение 2026-09-29: админка на том же ките). Mini App остаётся на `telegram-ui`.

**Что уходит из `apps/web`:** `@mui/material`, `@emotion/*`, `theme.ts`, `StyledEngineProvider`/CSS layers. `tokens.ts` остаётся как JS-копия цветов.

## 3. Токены

Токены задаём как CSS-переменные в формате shadcn (`--background`, `--primary` и т. д.) в `packages/ui/src/theme.css` и пробрасываем в Tailwind через `@theme inline`. Статусные цвета отчёта (`ok/warn/bad/none`, шкала ЛКП) **остаются как есть**, это ядро продукта.

### Цвета

| Токен | Значение | Где |
|---|---|---|
| `--background` | `#F6F7F8` | фон страницы |
| `--card` | `#FFFFFF` | карточки, bottom sheet |
| `--foreground` | `#111418` | основной текст |
| `--muted-foreground` | `#70757F` | подзаголовки, подписи |
| `--secondary` | `#EEF0F2` | вторичная кнопка, фон иконки в ячейке, поле ввода |
| `--secondary-foreground` | `#111418` | текст на вторичной кнопке |
| `--border` | `#E6E8EB` | используется редко: только разделитель ячеек внутри карточки |
| `--primary` | **акцент, см. ниже** | главная кнопка, активные элементы |
| `--primary-foreground` | зависит от акцента | текст на главной кнопке |
| `--ring` | = `--primary` с прозрачностью 40 % | фокус |
| `--destructive` | `= --color-bad` | ошибки |

**Акцент (решение за вами, меняется одной переменной):**

| Вариант | `--primary` | Текст на кнопке | Ощущение |
|---|---|---|---|
| **A. Синий** ✅ выбран 2026-09-29 | `#3B6CF6` | белый | спокойно, «надёжно» |
| B. Лайм | `#C6F432` | `#111418` | ближе всего к энергии Т-Банка (яркая кнопка + тёмный текст), при этом не жёлтый |
| C. Оранжевый | `#FF6B2C` | белый | тепло, заметно |

⚠️ **Зелёный как акцент не берём:** зелёный уже означает «норма» в отчёте, и кнопка «Купить» спорила бы со статусом ✅.

### Радиусы

| Элемент | Радиус |
|---|---|
| Карточка, bottom sheet (верхние углы) | 24 px |
| Кнопка, поле ввода | 16 px |
| Иконка в ячейке (кружок) | 50 % |
| Бейдж статуса | 999 px (пилюля) |

### Типографика (Onest)

| Стиль | Размер / межстрочный | Вес | Где |
|---|---|---|---|
| `display` | 32 / 36 | 700 | заголовок главной |
| `title` | 24 / 28 | 700 | заголовок экрана |
| `heading` | 20 / 24 | 600 | заголовок карточки |
| `body` | 16 / 22 | 400 | основной текст, **поля ввода (меньше 16 — iOS зумит страницу)** |
| `body-strong` | 16 / 22 | 600 | заголовок ячейки |
| `caption` | 13 / 16 | 400 | подзаголовок ячейки, подписи, `--muted-foreground` |
| `amount` | 17 / 22 | 600, `tabular-nums` | суммы в ячейках |

### Отступы и сетка

- Шаг 4 px. Поля экрана — 16 px, между карточками — 12 px, внутри карточки — 16 px.
- Контент — одна колонка `max-width: 480px` по центру. На десктопе вокруг просто серый фон: отдельной десктопной вёрстки в MVP нет.
- Высота кнопок: `lg` 56 px (главное действие), `md` 44 px, `sm` 36 px. Зона нажатия не меньше 44 px.
- Закреплённая снизу кнопка учитывает `env(safe-area-inset-bottom)`.

### Тени и движение

- Теней нет. Исключения: bottom sheet и закреплённая нижняя панель (мягкая тень вверх, `0 -4px 16px rgb(0 0 0 / 0.06)`).
- Длительность анимаций 150–250 мс, `ease-out`. Анимируются только bottom sheet (vaul), toast (sonner) и shimmer скелетона. `prefers-reduced-motion` отключает shimmer.

## 4. Компоненты

Всего ~15 штук, больше в MVP не нужно.

**Из shadcn (как есть, с нашей темой):**

| Компонент | Где |
|---|---|
| `Button` — варианты `primary`, `secondary`, `ghost`; размеры `lg/md/sm`; состояние `loading` (спиннер вместо текста, ширина не прыгает) | везде |
| `Input` — высота 56, фон `--secondary`, без рамки, рамка `--ring` в фокусе, ошибка текстом снизу | поиск, email, телефон |
| `InputOTP` | вход, шаг 2 |
| `Drawer` (vaul) | подтверждения, «Что такое VIN?», «Предыдущая оплата не завершена» |
| `Sonner` | ошибки мутаций |
| `Skeleton` | все загрузки |
| `Badge` | статус покупки |

**Наши составные (`packages/ui/src/components`):**

| Компонент | Что это |
|---|---|
| `AppHeader` | липкая шапка: слева «назад» или логотип, по центру заголовок (появляется при скролле), справа иконка «Покупки» / «Войти». Фон `--background` с `backdrop-blur` |
| `Card` / `CardGroup` | белая карточка r=24; `CardGroup` — карточка со списком ячеек и необязательным заголовком сверху |
| `Cell` | ячейка списка: `before` (иконка/аватар в кружке 40 px), `title`, `subtitle`, `after` (сумма, бейдж, шеврон). Кликабельная — вся строка, подсветка при нажатии |
| `BottomBar` | закреплённая снизу панель с главной кнопкой (и подписью над ней, например ценой) |
| `StatusScreen` | полноэкранный результат: иконка в большом круге (72 px, мягкий фон статуса), заголовок, текст, 1–2 кнопки. Для «Оплачено», «Не прошло», «Заявка принята», 404, «Нет связи» |
| `EmptyState` | то же, но внутри страницы: иконка, строка текста, кнопка |
| `Amount` | форматированная сумма (`formatByn`), `tabular-nums` |
| `OfflineBanner` | узкая плашка сверху «Нет интернета» |

## 6. Тексты и форматы

- **Суммы:** `45 BYN`, копейки только если они есть (`45,50 BYN`). Пробел-разделитель тысяч неразрывный (`1 500 BYN`). Это меняет пример в WEB-2 (`formatByn`).
- **Даты:** «12 сент», год только если не текущий («12 сент 2025»). Время — только на экране результата оплаты.
- **Телефон:** показываем в виде `+375 29 123-45-67`, отправляем `+375291234567`.
- **VIN:** моноширинно не выделяем, но даём кнопку «копировать».
- Кнопки — глаголом: «Найти», «Оплатить», «Получить код», «Хочу отчёт».

---

## 7. Доступность

- Контраст текста не ниже WCAG AA (проверить контраст белого текста на `#3B6CF6`: AA для крупного текста кнопок).
- Статус всегда = цвет + иконка + текст.
- Видимый фокус (`--ring`) — Radix даёт его из коробки, не отключаем.
- `lang="ru"`, осмысленные `aria-label` у иконок-кнопок в шапке.

## 8. Порядок внедрения

**DS-1** (0,5 дня) — самостоятельный нулевой шаг, выполняется **до** ADM-1 и WEB-1 (по итогам ревью, C-2 в `REVIEW_REPORT.md`: при порядке «админка раньше покупателя» ADM-1 зависит от DS-1, поэтому DS-1 не может быть частью WEB-1). - [ ] Onest подключён через `@fontsource-variable/onest`;

- [ ] витрина компонентов `/dev/ui` показывает все компоненты во всех состояниях — по ней принимаем дизайн. Строится в первом создаваемом приложении, сейчас это `apps/admin` (минимальный каркас, без бизнес-экранов);

Удаление MUI и emotion из `apps/web` (`main.tsx` без `ThemeProvider`/`StyledEngineProvider`, `<Toaster />` подключён) в DS-1 **не входит** — это пункт WEB-1 в `PLAN_FRONTEND.md`.
